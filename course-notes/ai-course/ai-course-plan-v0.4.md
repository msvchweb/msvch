전체 12강 중 1~8강. GitHub·Vercel 가입·연동과 나만의 앱 제작은 9강부터 시작한다.

> 진행 방식 개정: 현재 강의 진행은 [시연 중심 진행안 v0.5](ai-course-demo-plan-v0.5.md)와 [1강 시연 시나리오](ai-course-lesson-1-demo-script-v0.1.md)를 따른다. 아래의 1강 24장 구성과 공통 모임 사례는 이전 슬라이드 제작 기록이다.

[강의안 v0.3](ai-course-8-week-plan-v0.3.md)을 바탕으로 에이커의 ChatGPT Work 활용 영상을 참고해 1강을 새로 구성했다. 기존 과정의 요청 정리·계획·검토·진행 기록은 유지하고, 한 강의를 여러 수업에 나누어 진행할 수 있도록 강의 단위로 정리했다.

**현재 상태:** 사용자 지시에 따라 1강을 새로 구성하고, 강의 선택·발표·현재 실습 자료의 표기를 강의 단위로 변경한다. 기존 week-N 주소는 연결을 유지하며, 로컬 미리보기에서 검토한다. 운영 사이트 배포는 별도다.

## 1. 이번 개정의 방향

수강생이 공부·업무·일상에서 쓰는 자료로 결과물을 만들고, 자주 쓰는 양식을 스킬로 저장해 다시 사용한다. 검토를 마친 절차를 예약과 모바일로 이어간다.

- 강의는 주제별 학습 단위다. 한 강의를 여러 번의 수업으로 나누어 진행할 수 있다. 과제의 20~30분은 참고 시간이다.
- 후속 강의의 공통 실습은 강의마다 한 가지를 중심으로 진행한다. 1강의 여러 기능 예제는 공통 실습과 선택 시연을 구분한다.
- 기본 도구는 ChatGPT와 Codex다. Claude는 같은 작업의 대응 기능을 비교할 때 사용하며 별도 유료 구독을 필수로 추가하지 않는다.
- 발표자료·회의록·이미지처럼 결과가 눈에 보이는 예제를 사용한다. 결과물의 품질은 직접 열고 원문과 비교해 확인한다.
- 가상 모임 자료를 공통으로 사용하고, 개인 적용에서는 팀 과제·공부 자료·모임 준비·업무 중 하나를 고른다.
- 인원 제한을 두지 않는다. 발표 시간은 참석 인원에 맞춰 조정한다.

8강을 마치면 수강생에게 프로젝트 지침, 다시 사용할 스킬, 검토한 결과물, 반복 실행 방법이 남아야 한다.

| 강 | 기존 실습 안에서 바꾸거나 보완할 부분 |
|---|---|

| 2강 | 두서없는 요청을 AI와 정리하고, 계속 쓸 지침과 이번 작업 조건을 나누기 |

### 공통 실습 자료

1강은 새 자료 묶음 `public/ai-course/lesson-1/materials/student-kit.zip`을 사용한다. 두 엑셀 준비표, 메모 이미지와 텍스트, 보고서·디자인 기준·가상 메일·진도 기록지가 들어 있다. 모든 이름과 일정은 가상이다.

2~8강 공통 자료는 `public/ai-course/materials/`에 있다. 자료의 사실관계는 유지하고 강의 단위 표기와 안내를 맞췄다. 같은 가상 모임을 다루되, 해당 강의가 지정한 파일을 기준으로 확인한다. Drive 사본·선택 시연용 음성·발표 참고 파일은 강사가 수업 전에 따로 준비한다.

| 자료 | 준비 기준 | 사용 강 |
|---|---|---|
| 빈 회의록과 좋은 예시 | 요약, 결정, 할 일, 확인 필요 사항을 구분 | 2·5강 |
| 짧은 전사본 A·C | 가상 모임 대화의 텍스트. C에는 누락·충돌 포함 | 3·5강 |

| 발표·이미지 참고 양식 | 사용할 수 있는 자료로 색상·배치 예시 준비 | 5강 선택 과제 |
| 변경된 모임 메모 | 기존 change-notes.txt 사용. 7강에는 모바일로 별도 검토 기한 지시 | 6·7강 |

## 4. 1강 — ChatGPT Work로 자료를 결과물로 만들기

**목표:** 사용할 환경과 자료를 확인하고, 실제 파일로 결과를 만든 뒤 원문과 비교한다. 여러 도구의 역할을 살펴보고 자신의 작업에 필요한 방법을 고른다.

참고 영상: 에이커, [퇴근시간이 빨라지는 챗지피티 워크 최신 활용법 10가지](https://www.youtube.com/watch?v=0CNv4dt8D5w). 2026-10-28에 공개 설명·예제와 한국어 자동 자막을 확인했다. 영상의 기능 사례를 참고하되, 대본·문장·실습 자료를 복제하지 않고 가상 모임 사례의 설명과 요청문을 새로 작성했다. 모델 이름이나 성능 비율을 수업의 보장 문구로 사용하지 않는다.

### 진행과 자료

24장 슬라이드를 사용한다. 고정된 총 소요 시간을 두지 않는다. 직접 실습은 파일 접근, 서로 다른 표 병합, 메모 이미지의 회의록 변환, 결과 확인을 중심으로 진행한다. 나머지는 계정·도구 지원 여부에 따라 강사 시연 또는 선택 실습으로 다룬다. 한 강의가 여러 수업에 걸쳐 진행되어도 번호는 1강을 유지한다.

| 슬라이드 | 내용 | 직접 확인할 것 |
|---|---|---|
| 1~5 | 결과 선택, 대화와 Work, 계정·앱·작업 범위 | 실제 가능한 기능과 연습 폴더 |
| 6~10 | 자료 받기, 폴더 확인, 엑셀 통합, 메모의 Word 문서화 | 원본6개 항목·미정 상태·실제 파일 |
| 11~15 | 구체적인 수정, 이미지·PPT·웹 발표의 선택 | 문구·날짜·글꼴·파일·미리보기 |
| 16~19 | 연결 도구, 가상 메일, 노트 표, 열린 앱 조작 | 가상 자료와 실제 연결·변경 범위 구분 |
| 20~22 | 스킬, 작은 시험 예약, 방법 선택 | 새 대화의 재사용·실제 실행·지원 조건 |
| 23~24 | 진도 기록과 마무리 | 마지막 슬라이드·결과 위치·다음 요청 |

새 자료 묶음에는 양식이 다른 XLSX2개, 자체 제작한 가상 메모 PNG와 같은 내용의 TXT, 발표용 보고서, 디자인 기준, 가상 메일, 진도 기록지가 있다. 메모 이미지는 실제 손글씨 사진이 아니라 정확한 글자로 만든 디지털 연습 자료다. 수강생이 자신의 공개 가능한 메모 사진에 적용하는 것은 선택으로 둔다.

### 작업 방식

처음에는 폴더와 읽을 파일 목록만 확인한다. 그다음 표의 열 이름을 대응시켜 여섯 항목을 새 파일로 합친다. 메모에서는 확정된 담당·기한과 미정·보류 상태를 구분해 회의록을 작성한다. 원본은 유지하고 결과물을 새 이름으로 저장한다. 도구가 파일을 만들었다는 말과 실제 파일이 열리는 것은 별도로 확인한다.

발표자료는 내용·디자인 기준·설치된 글꼴을 함께 지정한다. 외부 글꼴 주소만 주면 자동으로 설치되거나 모든 기기에서 같아진다고 안내하지 않는다. 웹 발표는 미리보기까지 다루며, 개인 앱 제작·외부 배포는9강부터 진행한다.

메일과 노트 앱은 먼저 가상 자료로 초안을 만든다. 실제 연결을 시연하면 사용할 계정·자료·권한·쓰기 위치를 확인한다. 초안 작성과 발송, 로컬 문서와 외부 서비스의 새 페이지를 구분한다. 열린 앱 조작은 지원되는 환경에서 연습용 파일 하나의 제목 색상을 바꾸는 작은 범위로 시연한다.

스킬은 검토를 마친 절차만 초안으로 만들고 다른 입력으로 시험한다. 예약도 수동 결과를 검토한 뒤 한 번만 시험하며, 로컬 실행의 컴퓨터·앱 조건과 실제 실행 기록을 확인한다. 상세 검증과 반복 관리 방법은5·6강에서 이어간다.

**진도 기록:** 강의 번호, 마지막 슬라이드, 직접 완료한 작업, 결과 파일, 원문에서 확인한 내용, 다음에 보낼 요청을 적는다. 다음 수업에는 같은 자료와 기록을 열어 이어간다.

**완료 확인:** 실제 읽은 자료와 저장 위치를 설명하고, 통합 준비표와 회의록을 열어 원문과 대조했으며, 직접 실행한 것과 시연만 본 기능을 구분한다. 기능 미제공은 실패한 사람으로 평가하지 않고 보완할 항목으로 기록한다.

## 5. 2강 — 프로젝트·지침·메모리

**목표:** 내가 하고 싶은 일을 AI와 정리한 뒤, 계속 적용할 기준과 이번 요청에만 필요한 내용을 구분한다. 5강에 스킬로 만들 참고 양식도 모은다.

| 순서 | 진행 |
|---|---|
| 1 | 1강의 결과 확인과 구체적인 수정 요청 돌아보기 |
| 2 | AI와 작업 요청을 정리하고 지침·개인 선호·메모리 구분 |
| 3 | 정리한 조건으로 프로젝트를 만들고 자료·작성 기준 추가 |
| 4 | 같은 자료로 준비표·안내문 대화를 나누어 실행 |
| 5 | 메모리·대화 관리 위치 확인, 참고 양식 정리 |
| 6 | 새 대화에서 기준이 적용되는지 확인 |

참고 양식은 빈 회의록, 팀 발표자료, 모임 안내문 중 하나면 된다. AI에게 예시에서 고정할 형식과 매번 바꿔야 할 내용을 구분하게 한다. 문서를 첨부한 상태와 스킬로 저장한 상태도 구분한다.

**작업 요청 정리:** [영상 11:30~15:26](https://www.youtube.com/watch?v=YAdZ-_mDeoo&t=690s)의 방법을 적용한다. 먼저 평소 말하듯 하고 싶은 일을 적고, AI가 빠진 조건을 질문하게 한다. 아래 여섯 항목을 짧게 채우면 된다. 전문 용어를 익혀 긴 요청문을 쓰는 과제로 만들지 않는다.

| 항목 | 우리 실습의 예 |
|---|---|
| 목적 | 모임 전에 준비할 일을 확인하기 |
| 입력 | 모임 메모와 준비 현황표 |
| 결과 | 할 일 표와 300자 이내 안내문 |
| 완료 기준 | 이름·날짜·인원을 원문과 비교하고 미정 사항 표시 |
| 작업 범위 | 새 파일 작성까지, 외부 발송은 제외 |
| 내 상황 | 처음 사용하는 앱이라 화면 위치부터 설명 필요 |

```text
모임 메모를 보고 준비할 일과 안내문을 정리하고 싶어.
내 생각을 바로 실행하지 말고, 작업 요청으로 먼저 정리해줘.
목적·사용할 자료·결과 형식·완료 기준·작업 범위를 짧게 적어줘.
결과를 바꿀 만큼 중요한 정보가 빠졌다면 한 번에 하나씩 물어봐.
내가 말하지 않은 날짜나 담당자는 임의로 정하지 마.
```

정리한 조건 중 반복할 기준만 프로젝트 지침에 넣는다. 설명 수준·선호하는 말투는 개인화 항목으로 검토하고, 이번 날짜·파일 위치·일시적인 컴퓨터 상태는 작업 요청에 둔다. 이를 전부 메모리에 저장시키지 않는다.

```text
이 자료에서 계속 적용할 작성 기준과 이번에만 쓰는 정보를 나눠줘.
프로젝트 지침에는 말투·결과 순서·누락 정보 처리 기준을 넣어줘.
예시의 이름과 날짜를 고정 규칙으로 넣지 마.
다음에도 사용할 참고 양식은 따로 표시해줘.
```

**과제:** 다른 자료를 같은 프로젝트의 새 대화에서 처리한다. 재사용할 참고 양식 하나를 준비한다.

**완료 확인:** 프로젝트의 새 대화에서 기준을 확인했고, 지침과 참고 자료를 다시 찾을 수 있다.

**이번 개정의 추가 확인:** 수강생이 막연하게 적은 요청과 질문을 거쳐 정리한 요청을 비교해 보여줄 수 있다.

## 6. 3강 — 클라우드·로컬과 파일 작업

**목표:** AI가 읽는 자료와 결과 파일의 위치를 확인하고, 짧은 계획을 검토한 뒤 로컬 폴더에서 새 결과물을 만든다.

Codex에서 실습 폴더를 열어 사용한다. GitHub 연결이나 앱 배포는 아직 시작하지 않는다. 로컬 작업도 필요한 내용이 AI 서비스로 전송될 수 있음을 설명한다. [로컬 작업 환경](https://learn.chatgpt.com/docs/enterprise/chatgpt-work-local-security#where-local-tasks-run)

| 순서 | 진행 |
|---|---|
| 1 | 프로젝트 지침 적용 결과 확인 |
| 2 | 클라우드·로컬·원격을 자료와 실행 위치로 구분 |
| 3 | 로컬 실습 폴더를 열고 작업 환경과 파일 위치 확인 |
| 4 | AGENTS.md 예시의 범위를 확인하고 짧은 실행 계획 검토 |
| 5 | 전사본과 현황표를 읽고 결과 폴더에 새 파일 저장 |
| 6 | 앱 밖에서 파일을 열고 원본 유지·작업 기록 확인 |

영상의 회의록 예제를 위해 강사는 짧은 녹음과 검토한 텍스트 전사본을 함께 준비한다. 공통 실습은 텍스트를 사용한다. 음성 파일 직접 처리는 수업 계정에서 미리 성공한 경우에만 선택 시연한다. 전사본의 이름·숫자·날짜도 원음과 대조할 대상이다.

**실행 전 계획:** [영상 15:28~17:49](https://www.youtube.com/watch?v=YAdZ-_mDeoo&t=928s)의 계획 확인 과정을 짧은 파일 작업에 적용한다. 수강생은 코드 구조를 평가하는 대신 사용 자료·할 일·저장 위치·원본 유지 여부가 맞는지 확인한다. Codex의 계획 모드는 실제 앱에서 제공되는 진입 방법을 사용한다. 현재 공식 안내는 입력창의 `/plan`을 설명한다. 영상 속 버튼 위치를 공통 사용법으로 고정하지 않는다. [공식 요청·계획 안내](https://learn.chatgpt.com/docs/prompting)

```text
나는 이 앱을 처음 쓰고 명령어도 잘 몰라.
현재 연결된 실습 폴더와 읽을 수 있는 입력 파일부터 확인해줘.
transcript-a.txt와 preparation-status.csv로 준비 상황을 정리하려고 해.
사용 자료·작업 순서·결과 위치·확인할 항목을 5줄 안팎으로 계획해줘.
이 단계에서는 결과 파일을 만들거나 원본을 수정하지 마.
내가 직접 해야 할 조작이 있다면 어느 화면에서 왜 하는지 설명해줘.
```

계획을 확인하고 필요한 부분을 고친 다음 실행을 요청한다.

```text
확인한 계획대로 실행해줘.
원본은 유지하고 ‘결과물’ 폴더에 새 Markdown 파일로 저장해줘.
문서 첫 줄에는 이 파일로 무엇을 확인할 수 있는지 한 문장으로 적어줘.
마지막에는 사용한 자료·저장 위치·아직 확인할 내용을 남겨줘.
```

앱 두 개에 같은 폴더를 연결하는 시연을 하더라도 한 작업이 끝난 뒤 다른 앱에서 결과 파일을 읽는다. 폴더를 공유한다고 채팅 기록·메모리·스킬이 자동 공유되는 것은 아니다. 두 앱에 같은 파일 수정을 동시에 맡기지 않는다.

실패한 경우에는 원인, 바꾼 조건, 다음에 먼저 확인할 항목을 세 줄로 기록한다. AI가 저장했다는 말만 듣지 않고 앱 밖에서 실제 파일을 연다. 기록용 새 양식을 배포할 필요 없이 기존 실습 기록에 적는다.

**과제:** 새 메모로 같은 작업을 실행한다. 4강에 사용할 가상 자료 사본 두 개를 개인 Drive 실습 폴더에 준비한다.

**완료 확인:** 입력·실행·저장 위치를 구분하고, 원본과 새 결과 파일을 직접 열었다.

## 7. 4강 — 플러그인과 외부 앱 연결

**목표:** 연결한 서비스에서 자료를 읽고, 같은 확정 정보를 수신자에 맞게 정리한다. 읽기·초안 작성과 외부 발송·게시의 차이를 설명할 수 있다.

공통 연결은 Google Drive 하나로 진행한다. 연결 과정과 실제 파일 읽기를 완료하는 데 집중한다. Gmail까지 모든 수강생의 추가 연결 과제로 요구하지 않는다.

| 순서 | 진행 |
|---|---|
| 1 | Drive 실습 자료와 로그인 확인 |
| 2 | 플러그인·스킬·서비스 연결과 읽기·쓰기 동작 구분 |
| 3 | 설치·개인 계정 인증·연결 상태 확인 |
| 4 | 지정한 자료 두 개를 찾고 제목·링크 확인 후 준비 상황 정리 |
| 5 | 연습용 주소록의 두 역할에 맞춰 안내문 초안 작성·비교 |
| 6 | 외부 행동 전 확인, 연결 오류를 설명해 도움받기, 결과 저장 |

```text
연결된 Drive의 실습 폴더에서 변경 메모와 준비 현황표를 찾아줘.
사용한 파일의 제목과 확인 가능한 링크를 보여줘.
두 자료에서 확정된 내용을 확인한 뒤 안내문 초안 두 개를 작성해줘.
진행 담당자에게는 준비할 일을, 참석자에게는 시간·장소를 중심으로 적어줘.
각 초안에 수신자와 역할을 표시하고 공통 날짜·장소를 일치시켜줘.
이 대화에 초안만 보여줘. 메일 발송이나 외부 저장은 하지 마.
```

영상의 메일 사례는 **수신자별 초안 → 이름·주소·본문 확인 → 전송 → 실제 도착 확인**의 순서로 설명한다. Gmail 전송 기능을 사전에 확인한 강사는 본인이 소유한 두 주소로 2~3분 선택 시연할 수 있다. 수강생용 가상 주소록과 실제 발송용 주소는 분리한다. 실제 교인·수강생 명단을 사용하는 일괄 발송은 공통 과제로 만들지 않는다.

**외부 행동 구분:** 두 번째 영상의 SNS 연결 사례에서는 자료 읽기, 초안 작성, 외부 게시가 각각 다른 행동임을 가져온다. 실제 연결 화면에서 어느 계정에 어떤 권한을 주는지 확인한다. 수업의 공통 결과는 검토할 초안까지이며, 발송·게시를 자동으로 승인하는 규칙을 만들지 않는다.

Threads 개발자 계정·비밀키·콜백 주소 설정은 이 강의 실습으로 추가하지 않는다. 영상에서도 Instagram 프로페셔널 전환은 Threads만 사용하는 데 필수는 아니라고 설명하므로 이를 가입 조건으로 옮기지 않는다. 세부 API 연결은 필요할 때 공식 안내를 다시 확인할 심화 주제로 남긴다.

**연결이 막혔을 때 연습할 요청:** 남은 검토 시간 안에 가상 오류 화면 하나로 시연한다. 화면을 보낼 때 계정 정보·인증 코드·비밀키는 가린다.

```text
Drive의 실습 폴더를 읽으려는데 이 화면에서 멈췄어.
직전에 한 조작은 [조작]이고, 화면의 문구는 [오류 문구]야.
현재 상태에서 먼저 확인할 항목과 다음 조작 하나를 설명해줘.
다른 방법이 있다면 필요한 권한과 달라지는 점도 알려줘.
연결하지 못했다면 자료를 읽었다고 가정하지 마.
```

허용된 연결이 안 되면 같은 가상 파일을 직접 첨부해 초안 실습을 이어갈 수 있다. 다만 ‘외부 연결 성공’과 ‘첨부 자료로 작업 성공’은 구분해 기록한다.

**과제:** 실습 폴더에 새 메모를 추가하고 다시 읽게 한다. 두 초안의 공통 사실이 일치하는지 확인한다.

**완료 확인:** 의도한 외부 자료를 읽었고, 근거 파일과 초안 두 개를 대조했다. 발송 성공은 공통 완료 조건에 넣지 않는다.

## 8. 5강 — 자주 쓰는 양식으로 스킬 만들기

**목표:** 참고 양식을 분석해 작업 순서와 결과 형식을 저장하고, 새 대화에서 다른 자료로 재사용한다.

첫 영상의 양식 재사용과 두 번째 영상의 결과물 기준을 함께 적용한다. 공통 실습은 회의록 양식 하나로 통일한다. 발표자료와 이미지는 아래 선택 과제에서 다룬다.

| 순서 | 진행 |
|---|---|
| 1 | 그럴듯하지만 빠진 결과와 기준을 충족한 결과 비교 |
| 2 | 고정 형식·매번 바뀔 내용과 작성·검토 역할 구분 |
| 3 | 양식·작성 절차·검토 기준을 포함한 스킬 작성·저장 |
| 4 | 전사본 A 작성 후 검토 역할로 대조하고 필요한 부분 수정 |
| 5 | 전사본 C로 재실행해 누락·충돌 처리 확인, 스킬 수정 |
| 6 | 스킬 위치·호출 방법·공유 범위와 선택 과제 안내 |

현재 공식 안내는 ChatGPT의 `@`, Codex의 `$`를 통한 스킬 선택을 설명한다. 제작 도우미는 해당 화면에서 `@skill-creator` 또는 `$skill-creator`로 사용한다. 실제 수업 계정에서 보이는 방법으로 시연한다. [스킬 제작과 호출](https://learn.chatgpt.com/docs/build-skills)

**결과물 완료 기준:** [영상 26:30~29:08](https://www.youtube.com/watch?v=YAdZ-_mDeoo&t=1590s)의 낮은 품질 보고서 사례를 참고한다. ‘보기 좋게’라는 요청 대신 아래 항목을 스킬에 넣고 결과와 직접 대조한다.

1. 요약 → 결정·할 일 → 확인 필요 사항 → 안내문 순서가 있다.
2. 할 일 표에 담당자·기한·상태·근거가 있으며, 미정 내용은 구분된다.
3. 이름·날짜·인원은 이번 입력에서 가져왔고 충돌의 양쪽 근거가 남아 있다.
4. 안내문은 확정 정보만 사용하며 300자 이내다.
5. 결과를 실제로 열 수 있고, 사용 자료와 저장 위치를 다시 찾을 수 있다.

```text
첨부한 빈 회의록과 좋은 예시를 바탕으로 ‘주간 업무 정리’ 스킬을 만들어줘.
입력은 회의 전사본과 준비 현황표야.
자료 확인, 결정·변경 사항 구분, 할 일 표 작성, 안내문 초안 작성 순서로 진행해줘.
결과는 요약, 결정·할 일 표, 확인 필요 사항, 안내문 순서로 만들어줘.
예시의 이름과 날짜를 고정 문구로 저장하지 마.
없는 정보는 추측하지 말고, 자료가 충돌하면 양쪽 근거를 남겨줘.
작업 절차는 초안 작성 → 원문·완료 기준과 대조 → 필요한 부분 수정으로 구성해줘.
검토 결과를 사람에게 보여주고, 외부 발송이나 게시까지 진행하지 마.
코드 없이 작업 지침과 참고 양식 중심으로 시작해줘.
저장 위치와 새 대화에서 호출하는 방법을 알려줘.
초안을 검토한 뒤 서로 다른 전사본 A와 C로 한 번씩 시험하자.
```

확인할 점: 저장됐다는 메시지만 보지 말고 새 대화에서 스킬을 찾아 호출한다. 두 번째 결과에도 첫 예시의 이름·날짜가 남아 있지 않은지 확인한다. 공유할 때는 사용 권한이 있는 가상 양식과 설명만 포함한다.

**작성과 검토 나누기:** 스킬의 작업 단계로 두 역할을 구분한다. 별도의 검토 연습에서는 새 대화에 원문 두 개와 초안을 함께 주고 아래 요청을 사용한다. 먼저 문제를 찾고 사람이 근거를 확인한 뒤, 작성 대화로 돌아가 필요한 항목만 고친다. 이 수업의 기본형은 순서대로 역할을 나누는 방식이며, 동시에 여러 에이전트가 실행됐다는 뜻은 아니다.

```text
지금은 초안 작성자가 아니라 검토자 역할로 확인해줘.
첨부한 원문 두 개와 초안을 직접 비교해줘.
이름·날짜·인원, 빠진 항목, 결정과 제안의 구분을 살펴봐.
문제가 있는 항목은 ‘초안 내용 / 원문 근거 / 고칠 점’으로 정리해줘.
원문이 충돌하거나 정보가 없으면 확정하지 마.
이 단계에서는 초안을 다시 쓰거나 외부로 보내지 마.
```

다른 AI의 동의나 다른 모델의 검토는 사실 확인을 대신하지 않는다. 추가 유료 구독 없이 같은 앱의 새 대화로 진행할 수 있다. 새 대화도 정확성을 보장하지 않으므로 마지막 원문 대조는 수강생이 한다.

A와 C의 결과는 서로 다른 이름으로 저장해 다음 시간에 다시 연다. 앱에서 파일을 만들 수 있다면 실제 파일을 확인하고, 해당 기능이 없으면 본인이 내용을 복사해 Markdown 문서로 저장한다. 스킬의 저장 위치와 실행 결과의 저장 위치는 구분한다.

**과제:** 새 자료로 공통 스킬을 다시 실행하거나, 아래 선택 과제 중 하나로 대체한다. 한 주에 모두 만들게 하지 않는다.

### 선택 A — 발표 양식 재사용

2강에 모은 발표 양식에서 색상·글자·배치를 분석하고, 다른 내용의 5장 발표자료를 만든다. 내용이 바뀌어도 양식이 적용되는지 확인한다.

```text
이 발표 예시의 색상, 글자 크기, 제목과 본문의 배치 기준을 정리해줘.
해당 기준을 재사용할 수 있는 발표자료 스킬로 만들어줘.
이번 주제는 ‘발표 모임 진행안’이고 표지 포함 5장이야.
예시의 문장과 이름을 복제하지 말고 내가 준 새 내용만 사용해줘.
완성한 자료를 실제로 열어 글자 넘침과 내용 누락을 검토하자.
```

편집 가능한 발표 파일이나 Google Slides 연결은 제공되는 환경에서 사용한다. 수업 전 내보내기를 확인한다. 발표자료 생성과 실제 파일 검토를 구분한다. [발표자료 제작·검토 예시](https://learn.chatgpt.com/use-cases/create-lesson-deck)

### 선택 B — 소개 앱의 배너 이미지

나만의 앱에 사용할 배너 한 장을 만든다. 이미지를 만든 뒤 문구와 배치 기준을 스킬에 정리하고, 다른 문구로 한 번 더 적용한다.

```text
나의 소개 앱에 넣을 가로 16:9 배너를 만들어줘.
문구는 ‘이번 주에 만든 것’ 한 줄이고 왼쪽에 배치해줘.
오른쪽에는 노트와 작은 식물 그림을 넣어줘.
크림색 배경과 짙은 남색을 사용하고 문구가 잘 보이게 해줘.
결과를 보고 문구·배치·색상 기준을 재사용할 이미지 제작 스킬로 정리하자.
```

이미지의 글자·배치·해상도를 직접 확인한다. 스타일 지침이 다음 이미지의 모든 픽셀을 똑같이 만드는 것은 아니다. 이미지 생성이 제공되지 않는 계정에서는 강사 결과를 검토하고, 본인 실행은 보완 항목으로 남긴다.

**완료 확인:** 스킬을 새 대화에서 찾고, 서로 다른 두 자료로 실행했으며, 누락·충돌 처리와 예시 내용의 잘못된 재사용을 확인했다.

## 9. 6강 — 준비 상황 브리핑 예약

**목표:** 검증한 스킬을 정해진 시간에 실행하고, 실제 실행 기록·생성 파일·검토 대기 상태를 확인한다.

공통 결과는 한 문서 안의 요약·할 일·확인 필요 사항·안내문이다. 첫 영상의 브리핑에 두 번째 영상의 상태 기록과 완료 기준을 적용한다. 결과가 생성된 것과 사람이 검토를 마친 것은 별도로 표시한다. 대시보드 앱 제작·배포는 9강 이후에 진행한다.

| 순서 | 진행 |
|---|---|
| 1 | 스킬과 현재 입력 자료 확인 |
| 2 | 실행 위치·자료·시간대, 등록과 실제 실행의 차이 설명 |
| 3 | 수동 실행을 검토한 뒤 수업 중 1회 시험 예약 |
| 4 | 일정·결과 위치 확인, 기다리는 동안 브리핑 검토 기준 연습 |
| 5 | 예약 실행 기록·생성 파일·검토 대기 상태 확인 |
| 6 | 주간 반복으로 변경하거나 일시 중지, 불필요한 시험 예약 정리 |

```text
이 로컬 실습 프로젝트에서 ‘주간 업무 정리’ 스킬을 사용해
현재 준비 상황의 브리핑을 만드는 예약을 설정하려고 해.
입력은 ‘입력자료’ 폴더의 지정한 모임 메모와 현황표야.
결과는 ‘결과물/모임준비-브리핑-YYYY-MM-DD.md’에 새 파일로 저장해줘.
기준 날짜와 사용한 파일을 적고, 없는 정보는 확인 필요로 남겨줘.
실제 실행 시각·입력 파일·결과 위치·실패 여부를 기록해줘.
결과를 만들었으면 ‘생성 완료, 사람 검토 대기’로 표시해줘.
외부 메일 발송은 하지 마.
반복 일정은 매주 월요일 오전 9시, 한국 시간이야.
먼저 일정·실행 위치·입력·저장 위치를 보여주고,
수업 중에는 내가 지정하는 시각에 1회 시험 실행부터 확인하자.
```

날짜를 바꿔 저장한 것과 새 자료를 처리한 것은 다르다. 과제에서는 입력 메모의 내용도 바꾸고, 바뀐 기한·담당자가 결과에 반영되는지 확인한다.

등록됨·실행 중·결과 생성·실패를 구분한다. 도구가 제공하는 실행 기록을 먼저 보고 결과 파일과 맞춰 확인한다. 요청문에 상태 기록을 넣었다고 실제 기록 기능이나 자동 중지가 보장되는 것은 아니다. 계속 실패하면 반복 일정을 중지하고 수동 실행에서 원인을 확인한다. AI가 결과를 생성한 뒤 사람이 원문을 대조해 검토 완료를 기록한다.

예약이 로컬 파일을 사용하면 컴퓨터와 앱이 실행 중이어야 한다. 웹 예약은 업로드 자료나 연결 도구를 사용할 수 있지만 컴퓨터의 폴더를 직접 읽지 않는다. [현재 예약 안내](https://learn.chatgpt.com/docs/automations)

관심 분야 뉴스 브리핑은 선택 시연으로 둔다. 링크·발행일·원문 대조를 포함하고, 출처가 없거나 확인하지 못한 소식은 확정 사실로 넣지 않게 한다. 영상에 나온 뉴스 제목을 그대로 수업의 사실 자료로 사용하지 않는다.

**과제:** 바뀐 자료로 실제 예약 실행을 한 번 확인한다. 실행 시각·입력·결과를 기록하고 불필요한 예약은 중지한다.

**완료 확인:** 예약이 실제 시각에 시작한 기록, 열어 본 결과 파일, 일정 수정·중지 방법이 있다.

## 10. 7강 — 모바일에서 작업 이어가기

**목표:** 연결된 컴퓨터의 같은 프로젝트에 휴대폰으로 작업 대상과 수정 범위를 지정하고 결과·진행 기록을 확인한다.

| 순서 | 진행 |
|---|---|
| 1 | 6강 예약 결과와 모바일 로그인 확인 |
| 2 | 클라우드 대화 열기와 컴퓨터 원격 작업 구분 |
| 3 | 각자 지원되는 기기 연결·페어링 |
| 4 | 모바일에서 프로젝트·파일·수정 범위를 지정해 같은 스킬 실행 |
| 5 | 실제 실행 컴퓨터·결과 파일·변경 기록 확인 |
| 6 | 연결 관리, 전원·절전·네트워크 문제 확인 |

```text
연결된 컴퓨터의 AI 실습 프로젝트에서 기존 브리핑 작업을 이어가줘.
먼저 실제 연결된 컴퓨터·프로젝트·수정할 파일을 확인해줘.
초안 작성 기한인 11월 12일은 유지하고,
별도 검토 기한을 2026년 11월 13일(금) 오후 3시로 표시해줘.
검토 담당자는 확인 필요로 남겨줘.
‘주간 업무 정리’ 스킬로 새 버전을 만들고 원본은 유지해줘.
바뀐 항목·저장 위치·진행 상태를 알려줘. 외부 발송은 하지 마.
```

모바일 원격은 기존 필수 주제로 유지한다. 두 번째 영상의 막힌 화면 설명 방법만 연결 문제 대응에 적용한다. 접속한 컴퓨터와 파일 위치부터 확인하고, 연결할 수 없는 컴퓨터에서 작업했다고 간주하지 않는다. 개강 전 [원격 연결 안내](https://learn.chatgpt.com/docs/remote-connections)와 실제 기기 제공 여부를 다시 확인한다.

**과제:** 컴퓨터를 켜둔 상태에서 다른 장소의 휴대폰으로 같은 작업을 한 번 이어간다.

**완료 확인:** 요청을 보낸 기기와 작업이 실행된 컴퓨터를 구분하고, 컴퓨터에 저장된 새 결과를 확인했다.

## 11. 8강 — 내 작업 종합 실습

**목표:** 요청·작성·검토·최종 확인의 역할과 완료 기준이 있는 절차 하나를 완성하고, 앱으로 만들면 편할 부분을 정한다.

| 순서 | 진행 |
|---|---|
| 1 | 개인 과제의 범위 확인 |
| 2 | 입력·결과·작업 순서·완료 기준을 짧게 정하고 확인 |
| 3 | 서로 다른 두 입력으로 작성·검토·수정 실행 |
| 4 | 다른 대화의 검토와 짝 대조, 대표 결과 공유. 선택 시연은 이 안에서 진행 |
| 5 | 다음 실행 방법과 앱으로 만들 불편함 기록 |

| 적용할 일 | 입력과 결과 | 9강 앱으로 이어질 수 있는 부분 |
|---|---|---|
| 팀 발표 준비 | 회의 메모 → 할 일 표·발표자료 | 팀 자료와 마감일을 모아 보는 화면 |
| 공부 자료 정리 | 학습 메모 → 요약·확인 문제 | 주제별 자료와 복습 내용을 여는 화면 |
| 모임 준비 | 변경 메모·현황표 → 브리핑·안내문 | 준비 상황과 미정 항목을 보는 화면 |
| 개인 작업 정리 | 작업 기록 → 진행 보고·다음 할 일 | 기록과 결과물을 모아 두는 화면 |

선택한 도구만 사용한다. 모든 프로젝트에 연결·스킬·예약·모바일을 전부 넣는 것을 수료 조건으로 삼지 않는다.

**기본 역할 분담:** 사람이 목적과 완료 기준을 정한다 → 작성 대화가 결과를 만든다 → 다른 검토 대화가 원문과 비교한다 → 사람이 수정할 내용과 최종 결과를 확인한다. 두 번째 영상의 여러 직원 구조는 이 네 단계로 줄인다. 검토 결과가 길어지면 필수 수정 사항만 먼저 고치고, 추가 제안은 다음 작업으로 기록한다.

개인 결과에도 5강와 같은 방식으로 완료 기준을 3~5개 적는다. 예를 들어 공부 자료라면 ‘원문 범위 표시, 핵심 개념 세 가지, 확인 문제 다섯 개, 정답 근거, 미확인 정보 구분’처럼 실제로 확인할 수 있는 항목을 쓴다.

**선택 시연 — 실제 하위 에이전트 두 개:** 지원되는 수업 계정에서만 30~50분 검토·공유 시간 중 최대 5분을 사용한다. 자료와 초안을 주고 서로 독립적인 검토 항목 두 개를 나눈다. 작성이 끝나기 전에 검토를 동시에 시작하지 않는다. 단순히 두 역할을 상상해 답하게 한 것과 실제 별도 작업이 실행된 것을 구분한다.

```text
첨부한 원문 두 개와 완성된 초안을 하위 에이전트 두 개로 병렬 검토해줘.
한 에이전트는 이름·날짜·수치를, 다른 에이전트는 누락·충돌·완료 기준을 확인해줘.
둘 다 같은 원문과 초안을 읽고 문제와 근거만 보고하게 해줘.
검토 중 원문이나 초안 파일은 수정하지 마.
두 결과가 모두 나온 뒤 중복을 합쳐 내가 확인할 목록을 만들어줘.
수정과 최종 확정은 검토 결과를 확인한 뒤 진행하자.
```

이는 강사용 선택 시연이며 필수 결과물을 늘리지 않는다. 실제 하위 에이전트 사용 시 작업별 실행·결과를 확인하고 사용량도 살핀다. 별도 작업마다 모델·도구를 사용해 단일 실행보다 토큰 사용이 늘 수 있다. 지원되지 않거나 남은 시간이 부족하면 기본형의 새 대화 검토로 끝낸다. [공식 하위 에이전트 안내](https://learn.chatgpt.com/docs/agent-configuration/subagents)

**최종 결과물:** 두 입력의 검토 기록과 결과 한 세트, 사용할 지침·스킬, 역할·완료 기준을 포함한 실행 안내 한 페이지, 앱으로 만들 불편함 한 가지.

실행 안내에는 목적, 입력 위치, 실행 요청, 결과 위치, 작성·검토·최종 확인 담당, 완료 기준, 실패했을 때 할 일, 예약을 사용했다면 중지 방법을 적는다.

**과제:** 새 자료로 같은 절차를 한 번 더 실행하고, 이전 방식과 비교해 걸린 시간과 아직 직접 확인할 일을 기록한다.

**완료 확인:** 서로 다른 입력으로 두 번 이상 실행했고, 다른 날에도 따라 할 수 있는 안내가 남아 있다.

## 12. 9강 이후와 연결

9강부터 GitHub·Vercel 가입·연동과 첫 앱 배포를 시작한다. 8강에 정한 불편함을 앱 주제로 삼는다. 기본 앱은 직접 입력하거나 검토한 파일을 사용하는 작은 범위로 시작한다.

영상의 대시보드 아이디어는 ‘자료와 결과를 한 화면에서 확인하는 내 앱’으로 발전시킬 수 있다. 처음에는 가상 자료로 화면과 수정·배포 과정을 익힌다. 실제 메일이나 개인 자료를 보여주려면 접근 권한과 공개 범위를 별도로 설계한다.

소개 앱을 선택한 수강생은 5강의 배너와 발표 결과물을 재사용한다. 배포 후에도 바꿀 내용을 요청하고, 미리보기에서 확인한 뒤 다시 배포하는 과정을 반복한다.

두 번째 영상의 관리 화면은 향후 앱의 참고 사례로만 사용한다. 처음부터 직원 조직·메신저·SNS 발행까지 넣기보다, 내 앱에 필요한 ‘작업 요청 / 진행 상태 / 결과 보기 / 검토할 항목’ 중 최소한의 화면을 고른다. 8강의 실행 안내와 완료 기준을 9강 앱 요청문에 재사용한다. Threads API나 무인 SNS 운영을 9강 공통 과제로 추가하지 않는다.

## 13. 강사 준비와 검토 기준

- 1강 새 자료 묶음의 엑셀·메모·보고서와 후속 강의의 전사본·현황표를 구분한다.
- 4강 전에 Drive 자료 읽기와 계정 연결을 실제 수업 계정에서 시험한다. Gmail 선택 시연은 본인 주소로 먼저 확인한다.
- 5강 전에 참고 양식의 사용 권한을 확인하고, 새 대화에서 두 자료로 스킬을 실행한다. 발표·이미지 선택 과제의 생성·열기 기능도 확인한다.
- 6강 전에 시험 예약이 실제로 시작되는지 확인한다. 사용량·실행 위치·시간대·결과 위치를 기록한다.
- 7강 전에 기기별 원격 연결을 확인한다. 기능 미제공으로 직접 못한 항목은 시연을 본 것과 구분해 보완 대상으로 남긴다.
- 추가 영상의 요청 정리·짧은 계획·검토 요청을 가상 자료로 각각 실행해 보고, 지정한 시간 안에 끝나는지 확인한다.
- 실제 하위 에이전트는 8강 선택 시연 전에 계정 제공 여부·실행 표시·소요 시간·사용량을 확인한다. 모델별 우열이나 AI 검토의 정확성을 보장하지 않는다.
- 요청문에 적은 작업 범위와 실제 앱의 권한 설정은 구분해 설명한다. 비밀키·계정 정보가 나온 화면은 시연 자료에서 가린다.

각 강의에서 네 가지를 확인한다: **의도한 자료를 사용했는가 / 요청한 형식인가 / 원문과 맞는가 / 다음에도 실행할 수 있는가.**

스킬·플러그인·예약·발표자료 안내는 2026-10-26~28에 공식 문서를 확인했다. 1강의 Work 기능과 로컬 실행 조건도 2026-10-28에 추가 검토했다. 자료와 슬라이드는 준비되어 있으며, 실제 수업 계정의 제공 기능을 확인하고 요청문을 리허설하는 일은 강사 준비에 포함한다.
