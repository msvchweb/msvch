## 2. 기술 스택 추천

### 2.1 프레임워크: Next.js (App Router)

**선정 근거:**
- SSG(정적 생성)로 대부분의 페이지를 빌드 타임에 생성 → 빠른 로딩
- 100명 이하 트래픽에서 서버 부하 최소화
- React 기반으로 풍부한 생태계 활용
- ISR(Incremental Static Regeneration)으로 콘텐츠 업데이트 시 전체 재빌드 불필요
- SEO 최적화 기본 내장 (메타태그, OG, 사이트맵 자동 생성)

### 2.2 스타일링: Tailwind CSS

**선정 근거:**
- 유틸리티 기반으로 빠른 UI 개발
- 반응형 디자인 쉽게 구현
- 번들 사이즈 최소화 (사용한 클래스만 포함)

### 2.3 CMS (콘텐츠 관리): Notion API 또는 Sanity

교회 관리자가 코드 수정 없이 콘텐츠를 관리할 수 있어야 함.

| 옵션 | 장점 | 단점 |
|------|------|------|
| **Notion API (추천)** | 교회 관리자가 Notion으로 글 작성 → 자동 반영, 학습 비용 최소 | API 호출 제한, 이미지 URL 만료 처리 필요 |
| **Sanity (무료 티어)** | 전용 CMS 대시보드, 이미지 CDN 내장, 실시간 미리보기 | 별도 관리 화면 학습 필요 |
| **MDX 파일 기반** | 가장 단순, 비용 0원 | 관리자가 Git 사용해야 함 (비개발자에게 부적합) |

> **추천**: 관리 편의성을 고려하면 **Notion API** 또는 **Sanity 무료 티어**. 개발자가 직접 관리한다면 **MDX 파일 기반**도 충분.

### 2.4 데이터베이스 (회원/그룹 기능용)

- **Supabase (무료 티어)**: PostgreSQL 기반, 인증/스토리지 내장, 100명 규모에 무료 티어로 충분
- 회원 로그인, 그룹 토론, 주보 게시 등 동적 기능에 활용

### 2.5 미디어/영상

- **YouTube 임베드**: 설교 영상은 YouTube에 업로드 후 임베드 (스토리지 비용 0원)
- **이미지**: Cloudflare Images 또는 Supabase Storage (갤러리 사진)

## 3. 배포 인프라 추천

### 3.1 최적 추천: Cloudflare Pages (무료)

| 항목 | 내용 |
|------|------|
| **비용** | 무료 (100명 이하 트래픽에 충분) |
| **빌드** | 월 500회 빌드, 프로젝트당 1회 동시 빌드 |
| **대역폭** | 무제한 |
| **CDN** | 글로벌 엣지 네트워크 (한국 포함) |
| **SSL** | 자동 HTTPS |
| **커스텀 도메인** | msvch.org 연결 가능 |
| **서버리스 함수** | Workers (무료 10만 요청/일) — API Routes 대체 |

**왜 Cloudflare Pages인가:**
- Next.js SSG 호스팅에 최적
- 한국 서울 엣지 노드 존재 → 빠른 응답
- 무료 티어가 소규모 교회 사이트에 충분
- Workers로 간단한 서버 로직 처리 가능

### 3.2 대안 비교

| 플랫폼 | 무료 티어 | 장점 | 단점 |
|--------|-----------|------|------|
| **Cloudflare Pages** ⭐ | 무제한 대역폭, 500빌드/월 | 가장 빠른 CDN, 무제한 트래픽 | SSR 기능은 Workers 설정 필요 |
| **Vercel** | 100GB 대역폭, 상업용 시 유료 | Next.js 공식 지원, DX 최고 | 교회=조직 → Pro 플랜 요구 가능성 |
| **Netlify** | 100GB 대역폭, 300빌드분/월 | 간편한 배포, 폼 처리 내장 | 한국 CDN 노드 없음 |
| **GitHub Pages** | 무료 | 가장 단순 | 정적 파일만, 서버 기능 없음 |

### 3.3 추천 인프라 구성도

```
┌─────────────────────────────────────────────────┐
│                    사용자 (브라우저)                │
└──────────────────────┬──────────────────────────┘
                       │
              ┌────────▼────────┐
              │  Cloudflare CDN  │  ← 글로벌 엣지 (서울 노드)
              │  (Pages + DNS)   │  ← SSL 자동, 커스텀 도메인
              └────────┬────────┘
                       │
          ┌────────────┼────────────┐
          │            │            │
   ┌──────▼──────┐ ┌──▼───┐ ┌─────▼─────┐
   │  정적 페이지  │ │Workers│ │ Supabase  │
   │  (SSG/ISR)  │ │(API)  │ │ (DB/Auth) │
   │  Next.js    │ │       │ │ Storage   │
   └─────────────┘ └──┬───┘ └───────────┘
                       │
              ┌────────▼────────┐
              │  외부 서비스      │
              │  - YouTube API  │
              │  - Notion API   │
              │  - Google Maps  │
              └─────────────────┘
```

## 4. 페이지/기능별 구현 전략

### 4.1 정적 페이지 (SSG)
빌드 타임에 생성, 변경 시 재빌드 또는 ISR.

- 홈, 인사말, 교회 소개, 오시는 길
- 예배 안내, 시간표
- 교회학교 (유아/초등/청소년/청년)
- 문화사역 (문화, 미용, 탁구, 반찬)
- 봉사자, 자원봉사

### 4.2 동적 콘텐츠 (ISR 또는 API)
CMS에서 관리, 주기적 갱신.

| 기능 | 구현 방식 |
|------|-----------|
| **공지사항** | CMS(Notion/Sanity) → ISR (1시간 재검증) |
| **주보** | 주간 PDF 업로드 또는 CMS 포스트 |
| **갤러리** | Supabase Storage + Lightbox UI |
| **설교 영상** | YouTube Data API → 자동 목록 생성 |
| **블로그/소식** | CMS → ISR |

### 4.3 인터랙티브 기능

| 기능 | 구현 방식 |
|------|-----------|
| **회원 로그인** | Supabase Auth (이메일/소셜 로그인) |
| **그룹 토론** | Supabase DB + 실시간 구독 |
| **오시는 길** | Google Maps Embed API (무료) 또는 Kakao Map |

## 7. 기술적 고려사항

### 7.1 Wix에서 마이그레이션 시 주의점
- **콘텐츠 백업**: Wix의 블로그 포스트, 이미지, 그룹 토론 데이터를 사전 내보내기
- **URL 리다이렉트**: 기존 Wix URL 패턴(`/post/...`, `/group/...`)에서 새 URL로 301 리다이렉트
- **SEO 유지**: 기존 인덱싱된 페이지의 검색 순위 보존을 위한 리다이렉트 맵 작성
- **도메인 이전**: Wix 네임서버 → Cloudflare 네임서버로 변경 (DNS 전파 24~48시간)

### 7.2 관리 편의성
- 비개발자(목회자/사무원)가 콘텐츠를 직접 수정할 수 있는 CMS 필수
- 이미지 업로드 시 자동 리사이즈/최적화 (next/image 활용)
- 모바일 우선 설계 (교인 대부분 스마트폰 접속 예상)

### 7.3 성능 목표
- Lighthouse 성능 점수 90+ (SSG 기반으로 달성 용이)
- 첫 페이지 로드 < 2초 (한국 기준)
- 이미지 lazy loading 적용
