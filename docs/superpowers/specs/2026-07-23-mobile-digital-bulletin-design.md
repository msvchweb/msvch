# 모바일 디지털 주보 디자인 명세

- 작성일: 2026-07-23
- 대상: 공개 주보 `/weekly`, `/weekly/[id]` 및 관리자 주보 편집
- 상태: 사용자 승인 완료

## 1. 목표

현재 공개 웹 주보는 A5 인쇄용 4개 면을 모바일 폭에 맞춰 축소해서 보여준다. 이를 종이 주보의 복제본이 아니라 예배 중 실제로 사용하는 모바일 전용 주보로 바꾼다.

새 주보는 다음을 달성해야 한다.

1. 접속 시 한국 시간 기준으로 현재 또는 가장 가까운 예배를 자동 선택한다.
2. 선택한 예배에 필요한 순서만 보여준다.
3. 예배 시간에는 라이브 영상을, 지난 주보에는 연결된 설교 영상을 같은 화면에서 볼 수 있다.
4. 사도신경, 찬송가, 성경 본문 등은 화면을 벗어나지 않고 바로 열어 볼 수 있다.
5. 예배순서 다음에 다음 주 기도·헌금·안내위원과 교회소식만 간결하게 제공한다.
6. 관리자가 예배별 순서, 상세자료, 라이브, 지난 영상을 실제로 운영할 수 있다.
7. 기존 인쇄 주보의 화면과 출력 결과는 변경하지 않는다.

## 2. 현재 구조와 제약

- `weeklies`는 주일예배 순서, 수요예배, 위원, 교회소식 등 대부분을 JSONB 필드로 저장한다.
- 금요기도회 순서, 예배별 정확한 시작·종료 시각, 주보별 라이브·녹화 영상 연결, 사도신경·찬송가·성경 전문 자료실은 없다.
- 공개 웹은 `BulletinWebView`가 인쇄 컴포넌트 `BulletinFront`와 `BulletinBack`을 4면으로 축소 표시한다.
- 인쇄 컴포넌트에는 레이아웃 고정 주석이 있으므로 모바일 개편에서 수정하지 않는다.
- 설교 영상은 `sermon_videos`에 누적되며 제목으로 주일·수요·금요 등을 구분할 수 있다.
- 사이트에는 모바일 하단 전역 탭이 이미 있으므로 주보 전용 하단 내비게이션을 추가하지 않는다.
- 성경 번역문과 찬송가 가사는 저작권 또는 이용 조건을 확인한 자료만 전문으로 등록한다.

## 3. 검토한 접근법

### 3.1 세로형 예배 동반자 — 채택

영상, 예배순서, 다음 주 섬김, 교회소식을 하나의 세로 흐름으로 배치한다. 예배 흐름을 그대로 따라갈 수 있고, 큰 글자와 익숙한 스크롤 방식으로 고령 사용자도 쉽게 사용할 수 있다.

### 3.2 카드형 대시보드

원하는 정보를 빠르게 찾기 쉽지만 예배순서가 여러 카드로 분절되어 예배 중 읽는 흐름이 약하다.

### 3.3 전체화면 단계형 예배 모드

한 순서씩 집중하기 좋지만 전체 순서를 한눈에 보기 어렵고, 실제 진행 상태를 관리하지 않는 환경에서는 사용자가 계속 넘겨야 한다.

## 4. 공개 모바일 경험

### 4.1 정보 구조

화면 순서는 고정한다.

1. 주보 헤더: 날짜, 절기, 예배명, 현재 상태
2. 라이브 또는 지난 설교 영상
3. 활성화된 예배 탭
4. 선택한 예배의 순서
5. 다음 주 섬김: 기도, 헌금위원, 안내위원
6. 교회소식
7. 지난 주보와 설교 목록 링크

개략적인 모바일 구조는 다음과 같다.

```text
┌─────────────────────────┐
│ 날짜 · 절기              │
│ 주일예배        ● LIVE   │
│ [ 라이브/설교 영상 ]     │
├─────────────────────────┤
│ 주일예배  수요예배  금요 │
├─────────────────────────┤
│ 예배순서                 │
│ 01 예배의 부름           │
│ 02 신앙고백  [내용 보기] │
│ 03 찬송  21장 [열기]     │
│ 04 성경봉독 [본문 보기]  │
│ 05 말씀                  │
├─────────────────────────┤
│ 다음 주 섬김             │
├─────────────────────────┤
│ 교회소식                 │
├─────────────────────────┤
│ 지난 주보 · 설교 더보기  │
└─────────────────────────┘
```

### 4.2 시각 디자인

- 흰색과 기존 `church-cream`을 바탕으로 사용한다.
- 해당 날짜의 절기색 토큰을 상태 배지, 활성 탭, 타임라인, 주요 버튼에 사용한다.
- 인터페이스 글꼴은 프로젝트의 Pretendard 계열을 유지한다.
- 본문 기본 크기는 모바일에서 16px 이상, 보조 정보는 13px 이상으로 한다.
- 주요 터치 대상은 최소 44×44px을 확보한다.
- 카드는 과한 그림자 대신 얇은 경계와 명확한 여백을 사용한다.
- 전환 효과는 상세자료 시트와 탭 전환에만 짧게 적용한다.
- `prefers-reduced-motion`에서는 전환과 이동 애니메이션을 제거한다.
- 데스크톱에서도 종이 4면으로 돌아가지 않고 약 720~800px의 읽기 좋은 중앙 열로 표시한다.

### 4.3 예배 탭과 자동 선택

- 탭에는 해당 주보에서 활성화한 예배만 표시한다.
- 서비스 종류의 기본값은 `sunday`, `wednesday`, `friday`, `other`이다.
- 한국 시간 기준으로 시작 15분 전부터 종료 30분 후까지를 해당 예배의 활성 구간으로 본다.
- 활성 구간인 예배를 자동 선택하고 `LIVE` 상태를 표시한다.
- 둘 이상의 활성 구간이 겹치면 시작 시각이 현재와 가장 가까운 예배를 선택한다. 차이가 같으면 기본 예배, 배열 순서 순으로 결정한다.
- 활성 예배가 없고 오늘 예정된 예배가 있으면 가장 가까운 다음 예배를 선택한다.
- 오늘 예정된 예배가 없거나 그 주의 모든 예배가 끝났으면 기본 예배인 주일예배를 선택한다.
- 지난 주보 상세는 기본 예배인 주일예배를 먼저 선택한다.
- 사용자가 탭을 직접 선택한 뒤에는 페이지를 떠날 때까지 자동 선택으로 덮어쓰지 않는다.
- 시간 판정은 브라우저에서 다시 계산하여 정적 재검증 주기 때문에 상태가 오래 남지 않게 한다.

### 4.4 예배순서와 상세자료

- 순서는 번호가 있는 세로 타임라인으로 보여준다.
- 각 항목은 순서명, 요약 내용, 담당자를 표시할 수 있다.
- 연결된 자료가 있을 때만 `내용 보기`, `본문 보기`, `찬송가 보기` 동작을 노출한다.
- 사도신경·찬송가·성경·일반 문구는 접근성 있는 하단 시트로 연다.
- 외부 자료만 있는 경우 하단 시트에서 출처와 외부 링크를 제공한다.
- 상세자료를 닫으면 실행한 버튼으로 포커스를 돌려주고 스크롤 위치를 유지한다.
- 전문이 없는 항목은 비활성 버튼을 만들지 않고 참조명만 표시한다.

### 4.5 영상

- 활성 구간이며 유효한 라이브 주소가 있으면 라이브 플레이어와 `LIVE` 배지를 노출한다.
- 활성 구간이 아니면 선택한 예배에 연결된 `sermon_videos.video_id`를 사용한다.
- 주보와 연결된 영상이 없으면 빈 플레이어를 만들지 않고 설교 목록 또는 교회 유튜브 채널 링크를 제공한다.
- 영상은 16:9 비율을 유지하고 지연 로딩한다.
- 브라우저에서 YouTube API를 호출하여 실제 방송 상태를 추정하지 않는다. 라이브 상태는 관리자가 설정한 주소와 시간 구간으로 결정한다.
- 사용자가 다른 예배 탭으로 이동하면 그 예배에 연결된 영상으로 전환한다.

### 4.6 다음 주 섬김과 교회소식

- `next_week_prayer`, `offering_members`, `guide_committee`를 재사용한다.
- 모바일에서는 부별 표를 작은 카드 또는 읽기 쉬운 행 형태로 표시한다.
- 값이 전부 비어 있는 섹션은 숨긴다.
- `news`만 공개 모바일 주보의 교회소식으로 사용한다.
- 첫 소식은 기본으로 펼쳐서 보여주고, 나머지는 제목 중심의 아코디언으로 표시한다.
- 회의, 봉사, 새가족, 후원 명단 등 이번 범위에서 제외한 종이 주보 정보는 모바일 주보에 중복 표시하지 않는다.
- 필요한 다른 정보는 기존 홈페이지 화면으로 연결한다.

### 4.7 최신 주보와 보관함

- `/weekly`는 최신 발행 주보를 디지털 주보로 바로 표시한다.
- 지난 주보는 현재처럼 최신 20개를 제공하되, 모바일에서는 간결한 날짜·제목 목록으로 둔다.
- `/weekly/[id]`도 동일한 디지털 컴포넌트를 사용한다.
- `photo_images`가 있는 기존 주보도 `mobile_services`가 있으면 디지털 주보를 우선한다.
- `mobile_services`가 없고 구조화된 기존 데이터도 변환할 수 없을 때만 사진형 주보를 최종 폴백으로 사용한다.

## 5. 데이터 설계

### 5.1 `weeklies.mobile_services`

`weeklies`에 `mobile_services jsonb NOT NULL DEFAULT '[]'::jsonb`를 추가한다. 한 주의 예배를 자체 완결형 스냅샷으로 저장한다.

서비스 객체의 논리적 형태는 다음과 같다.

```text
MobileService
- id: string                 // 주보 내 안정적인 식별자
- type: sunday | wednesday | friday | other
- label: string              // 화면 표시명
- startsAt: ISO datetime     // KST 오프셋 포함
- endsAt: ISO datetime       // KST 오프셋 포함
- primary: boolean           // 기본 예배, 최대 1개
- visible: boolean
- leader: string
- liveUrl: string | null
- videoId: string | null     // sermon_videos의 video_id
- items: MobileServiceItem[]
```

순서 객체의 논리적 형태는 다음과 같다.

```text
MobileServiceItem
- id: string
- label: string
- summary: string
- assignees: string[]
- emphasized: boolean
- visible: boolean
- resourceId: uuid | null
- externalUrl: string | null // 항목 전용 보조 링크가 필요한 경우
```

저장 시 다음 규칙을 강제한다.

- 서비스와 순서 ID는 한 주보 안에서 중복되지 않는다.
- `primary`는 보이는 서비스 중 최대 하나이며, 없으면 첫 서비스를 기본으로 본다.
- 종료 시각은 시작 시각보다 늦어야 한다.
- `videoId`는 존재하는 설교 영상만 허용한다.
- 라이브와 외부 링크는 허용된 HTTPS 주소만 저장한다.
- 문자열과 배열 개수에는 합리적인 최대 길이를 둔다.

### 5.2 `worship_resources`

반복 사용하는 예배 자료를 위한 테이블을 추가한다.

```text
worship_resources
- id uuid primary key
- kind text: creed | hymn | scripture | text | link
- title text
- reference text
- content text
- external_url text nullable
- source_label text nullable
- rights_note text nullable
- is_active boolean
- created_at timestamptz
- updated_at timestamptz
```

- 공개 읽기 RLS는 과거 주보가 비활성 자료도 계속 해석할 수 있도록 모든 자료에 허용한다. 공개 화면은 현재 주보에서 참조한 ID만 조회하며 자료 목록 화면은 제공하지 않는다.
- 관리자 권한이 있는 사용자만 생성·수정·비활성화할 수 있다.
- 주보가 참조하는 자료는 물리 삭제하지 않고 비활성화하여 과거 주보 링크를 보존한다.
- 비활성 자료는 새 주보의 자료 검색 결과에서 제외하지만 기존 참조에서는 계속 표시한다.
- 사도신경은 초기 자료로 등록한다.
- 성경과 찬송가 전문은 사용 권한이 확인된 경우에만 등록한다.
- 전문 제공이 불가능하면 제목·참조·출처 링크만 저장할 수 있다.
- 찬송가나 성경 자료에 전문을 저장할 때는 출처와 권리 메모를 필수로 검증한다.
- JSONB 내부 `resourceId`는 DB 외래키로 강제할 수 없으므로 저장 검증에서 존재 여부를 확인한다.

### 5.3 기존 데이터 호환

`mobile_services`가 비어 있는 기존 주보는 읽기 어댑터로 변환한다.

- 주일예배: `worship_leader`, `worship_items`, `sermon_title`, `sermon_pastor`, `closing_hymn` 등을 사용한다.
- 수요예배: `wednesday_service`로 기본 순서를 구성한다.
- 금요기도회: 기존 데이터가 없으므로 자동 생성하지 않는다.
- 위원과 소식: 현재 필드를 그대로 사용한다.
- 변환 결과는 읽기 시에만 생성하며 기존 레코드를 자동 덮어쓰지 않는다.
- 관리자가 `기존 주보 내용으로 생성`을 실행해 저장한 이후부터는 `mobile_services`가 우선한다.

## 6. 관리자 경험

### 6.1 주보 편집기

기존 `WeeklyForm`에 `모바일 주보` 탭을 추가한다. 기존 인쇄 관련 탭과 필드는 유지한다.

모바일 주보 탭은 다음 기능을 제공한다.

1. 기존 주일·수요 데이터로 모바일 예배 초안 생성
2. 주일·수요·금요·기타 예배 추가 및 활성화
3. 예배 시작·종료 시각과 기본 예배 지정
4. 예배순서 추가, 삭제, 표시 전환, 순서 이동
5. 순서별 요약, 담당자, 강조 설정
6. 자료실 검색 및 사도신경·찬송가·성경 자료 연결
7. 라이브 주소 입력
8. 설교 영상 검색 및 연결
9. 모바일 폭 미리보기

순서 정렬은 포인터 드래그만 강제하지 않는다. 위·아래 이동 버튼을 함께 제공하여 키보드와 터치 환경을 지원한다. 별도의 드래그 라이브러리가 필요하지 않으면 추가하지 않는다.

### 6.2 설교 영상 추천

- 기존 `sermon_videos`의 날짜와 제목 기반 카테고리를 사용해 선택한 예배와 가까운 영상을 추천한다.
- 자동 추천은 확정 저장이 아니며 관리자가 선택해야 연결된다.
- 추천 결과가 없으면 동기화된 전체 설교 영상에서 검색해 선택한다.
- 저장된 `videoId`가 이후 조회되지 않으면 관리자에게 경고하고 공개 화면에서는 폴백 링크를 사용한다.

### 6.3 예배 자료 관리

기존 마스터 관리 패턴을 따라 `/admin/masters/worship-resources` 화면을 추가한다.

- 자료 종류, 제목, 참조, 본문, 외부 링크, 출처, 권리 메모를 편집한다.
- 본문 미리보기와 활성·비활성 전환을 제공한다.
- 이미 주보에서 참조 중인 자료는 삭제 대신 비활성화를 안내한다.
- 자료 전문을 등록할 권한이 있는지 관리자가 확인할 수 있도록 출처와 권리 메모를 확인 항목으로 노출한다.

## 7. 컴포넌트와 데이터 흐름

### 7.1 공개 화면 경계

- 인쇄 경로는 기존 `Bulletin`의 `print` 모드를 그대로 사용한다.
- 공개 웹 경로는 새 `MobileBulletin` 서버 경계와 작은 클라이언트 상호작용 컴포넌트를 사용한다.
- 서버에서 주보, 마스터, 연결 가능한 예배 자료, 필요한 설교 메타데이터를 병렬 조회한다.
- 서버 컴포넌트는 데이터 조합과 초기 마크업을 담당한다.
- 클라이언트 컴포넌트는 자동 탭 선택, 사용자의 탭 선택, 상세자료 시트, 영상 전환만 담당한다.
- 전체 페이지를 클라이언트 컴포넌트로 만들지 않는다.

예상 컴포넌트 경계는 다음과 같다.

```text
MobileBulletin
├─ BulletinHero
│  └─ BulletinVideo
├─ ServiceTabs                 // client island
├─ WorshipOrder
│  └─ WorshipResourceSheet     // client island
├─ NextWeekServing
├─ ChurchNews
└─ BulletinArchiveLinks
```

### 7.2 관리자 경계

- 기존 폼의 저장 DTO에 `mobile_services`만 추가한다.
- 모바일 탭 내부 상태와 검증은 별도 모듈로 분리하여 거대한 `WeeklyForm`에 모든 로직을 넣지 않는다.
- 예배 초안 변환기는 공개 화면의 기존 데이터 호환 어댑터와 동일한 핵심 매핑을 재사용한다.
- 자료 관리 CRUD는 현재 관리자 권한과 Supabase RLS 패턴을 따른다.

## 8. 오류 처리와 보안

- 주보가 없으면 기존 준비 중 상태를 유지한다.
- `mobile_services` 파싱 또는 검증에 실패하면 기존 데이터 호환 어댑터를 사용한다.
- 호환 변환도 불가능하고 사진이 있으면 사진형 주보를 보여준다.
- 자료 조회에 실패하면 예배순서는 유지하고 상세자료 동작만 숨긴다.
- 라이브 또는 녹화 영상이 없거나 유효하지 않으면 플레이어 대신 설교 목록·교회 채널 링크를 보여준다.
- 사용자에게 내부 DB 오류나 스택을 노출하지 않는다.
- 자료 본문은 구조화된 일반 텍스트로 저장하고 React 텍스트 노드로 렌더링한다. `dangerouslySetInnerHTML`을 사용하지 않는다.
- 라이브 URL은 `youtube.com`, `youtu.be` 등 명시적으로 허용한 호스트와 HTTPS만 허용한다.
- 자료 외부 링크도 HTTPS를 기본으로 하며 새 창 링크에는 적절한 `rel` 속성을 사용한다.
- 공개 읽기와 관리자 쓰기를 RLS로 분리한다.

## 9. 접근성과 성능

- 서비스 탭은 적절한 탭 역할, 선택 상태, 키보드 이동을 지원한다.
- 하단 시트는 다이얼로그 이름, 포커스 트랩, Escape 닫기, 실행 버튼으로 포커스 복귀를 지원한다.
- 아이콘만 있는 버튼에는 접근 가능한 이름을 제공한다.
- `LIVE`는 색상뿐 아니라 텍스트로도 상태를 전달한다.
- 영상 iframe은 필요한 서비스에만 렌더링하고 지연 로딩한다.
- 인터랙션이 없는 영역은 서버 컴포넌트로 유지하여 클라이언트 JavaScript를 제한한다.
- 모바일에서 가로 스크롤이 생기지 않아야 한다.
- 콘텐츠가 길어도 레이아웃 높이를 고정하거나 잘라내지 않는다.

## 10. 검증 전략

### 10.1 단위 테스트

- KST 기준 활성 구간 시작·종료 경계
- 같은 날 가장 가까운 다음 예배 선택
- 모든 예배 종료 후 기본 예배 선택
- 사용자 선택이 자동 선택보다 우선하는 상태 전이
- 기존 주일·수요 데이터를 `MobileService`로 변환
- 잘못된 JSONB, URL, 중복 ID, 여러 기본 예배 검증
- 자료 연결과 누락 자료 폴백

### 10.2 컴포넌트 및 통합 검증

- 서비스 탭 전환 시 순서와 영상이 함께 바뀌는지 확인
- 사도신경·찬송가·성경 시트의 열기, 닫기, 포커스 복귀 확인
- 빈 위원·소식 섹션이 숨겨지는지 확인
- 관리자 입력 저장 후 재편집했을 때 데이터가 보존되는지 확인
- 기존 내용으로 초안 생성 후 인쇄 필드가 변경되지 않는지 확인
- 자료 비활성화 후 과거 주보가 안전하게 폴백하는지 확인

### 10.3 브라우저 및 회귀 검증

- 375px, 390px 모바일 뷰포트
- 데스크톱 중앙 열
- 키보드 탐색과 축소 동작 설정
- 최신 주보, 지난 주보, 기존 구조화 주보, 사진형 주보
- 인쇄 미리보기의 4면 배치가 변경되지 않았는지 비교
- 린트, 타입 검사, 관련 테스트, 프로덕션 빌드

## 11. 완료 기준

다음 조건이 모두 충족되면 기능이 완료된 것으로 본다.

1. 모바일에서 종이 4면 축소판 대신 세로형 디지털 주보가 표시된다.
2. 현재 예배가 자동 선택되고 사용자가 다른 활성 예배로 전환할 수 있다.
3. 라이브 또는 연결된 지난 설교를 같은 화면에서 재생할 수 있다.
4. 사도신경·찬송가·성경 자료를 하단 시트에서 편리하게 볼 수 있다.
5. 다음 주 기도·헌금·안내위원과 교회소식이 기존 데이터에서 표시된다.
6. 관리자가 모든 모바일 예배 데이터와 자료를 입력·수정할 수 있다.
7. 기존 주보도 별도 데이터 이관 없이 합리적으로 표시된다.
8. 오류·빈 데이터 상태가 깨진 UI 없이 폴백한다.
9. 접근성, 타입 검사, 린트, 빌드, 주요 브라우저 검증을 통과한다.
10. 인쇄용 주보의 구조와 출력 결과가 변경되지 않는다.

## 12. 제외 범위

- YouTube API를 통한 실제 방송 시작·종료 상태 실시간 감지
- 예배 진행자가 현재 순서를 실시간으로 송출하는 운영 콘솔
- 예배 중 채팅, 출석, 헌금 결제, 푸시 알림
- 전체 성경·찬송가 원문 데이터의 무단 수집 또는 배포
- 주보와 무관한 홈페이지 전역 레이아웃 또는 다른 콘텐츠의 개편
- 기존 인쇄 주보 레이아웃의 리팩터링
